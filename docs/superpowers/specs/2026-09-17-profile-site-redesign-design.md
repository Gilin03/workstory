# BR-A 자기소개 사이트 전체 재구성 설계

## 목적

처음 방문한 사람이 3분 안에 김태빈의 고난, 다시 움직인 행동, 현재의 일하는 방식을 이해하고 “함께 일하고 싶은 이유”를 하나 말할 수 있는 지원용 사이트를 만든다. 공유된 Figma의 차콜·오렌지·크림 분위기는 유지하되, 숫자판이 주인공처럼 보이지 않도록 9번 서사의 자기소개 본편을 화면의 중심으로 둔다.

## 감사 결과와 설계 판단

현재 승인 콘텐츠의 이야기 본문은 세 문단 합계 약 568자로, 과제의 1,500자 안팎 목표보다 짧다. 또한 히어로의 통계와 별도 기록 보드가 숫자를 반복해 이야기보다 먼저 읽히고, 능력 영역은 이야기의 내용을 다시 설명해 중복된다. checklist의 전체 상태도 공개 URL·이메일·제출 현황 원자료가 남아 있는데 `완료`로 표시되어 상태가 모호하다.

따라서 이번 재구성은 다음을 원칙으로 한다.

1. 자기소개 본편을 가장 큰 콘텐츠 영역으로 확장한다.
2. 자기조절력·대인관계력·자기동기력은 별도 자랑 목록이 아니라 이야기 속 행동의 변화로 보여 준다.
3. 회복탄력성과 과제지속력은 13주 기록의 숫자로 뒷받침하되, 작은 근거 영역으로 낮춘다.
4. 출석률은 표시하지 않는다. 출석 기록은 결석 0일과 확정 출석 26/27일을 출처가 있는 보조 정보로만 사용한다.
5. 제출 현황 원자료가 없으므로 제출률은 만들지 않는다.
6. 소설적인 표현이나 확인되지 않은 업무·성과는 추가하지 않고, `assignment09_narrative.md`와 입력 기록의 사실만 사용한다.

## 사실의 기준

- 고난과 변화: `assignment09_narrative.md`의 7~9번
- 세 능력의 연결 근거: 9번의 최종 강점 지도와 직접 고른 기록
- 현재 장면: 2026-08-28 경청, 2026-09-07 n8n 복구 도움, 2026-09-08 정독·설명, 2026-09-09 부정적 일을 성장의 계기로 받아들인 기록
- 회복·지속의 수치: `inputs/ritual-history.json`의 23회 실천 기록과 26일 기록을 연 날
- 출석 보조 수치: `inputs/attendance.json`의 결석 0일, 확정 출석 26/27일, 9/17 확정 전 1일
- 제출 현황: 원자료가 없으므로 숫자 미산출
- 대표작: 10번 논문 PDF
- 13번 앱: 아직 없으므로 링크 없는 준비 카드

### Hero

이름과 `질문하고, 끝까지 확인하며 함께 해결하는 사람`을 먼저 보여 준다. 숫자 통계는 제거하고, 우측 차콜 패널은 이 사람의 실제 업무 방식을 `질문 → 확인 → 공유` 세 단계로 설명하는 시각 요소로 바꾼다. 2022—2026은 장식용 선이 아니라 “변화의 범위”를 설명하는 작은 캡션으로만 남긴다.

### 이야기

9번 1인칭 완성본을 바탕으로 1,300~1,500자 내외의 본편을 다시 쓴다. 순서는 ① 2022년 창원 PCB 제조업체에서 낯을 가리고 질문하지 못했던 고난, ② 먼저 인사하고 제때 질문하며 관계를 만든 전환, ③ 2026년 교육과정에서 경청·도움·정독·성장 기록으로 이어지는 현재다. 각 장면에는 날짜·장소 또는 상황·행동·배운 점을 함께 둔다.

화면에서는 세 장면을 넓은 본문 행으로 배치한다. 왼쪽에는 날짜와 장면 이름, 가운데에는 해당 능력, 오른쪽에는 충분한 줄 길이의 본문을 둔다. 본문과 메타 정보 사이에는 분리선을 두되, 모바일에서는 한 열로 내려 자연스럽게 읽히게 한다.

### 능력 지도

이야기를 다시 길게 반복하지 않는다. 세 능력을 “그때의 어려움 → 바꾼 행동 → 지금의 방식” 세 칸으로 짧게 요약한다.

- 자기조절력: 불편함을 인정하고 질문·확인이라는 다음 행동으로 바꾼 힘
- 대인관계력: 먼저 인사하고 듣고 묻고 함께 해결하는 힘
- 자기동기력: 부정적인 일을 성장의 계기로 바꾸고 다시 움직이는 힘

각 요약에는 해당 이야기를 가리키는 날짜와 9번 서사 문서 출처를 남긴다.

### 기록 근거

숫자 영역은 이야기 다음에 작고 명확하게 둔다. 핵심 짝은 다음과 같다.

- 회복탄력성 ↔ `23회 실천했다고 남긴 날` / 리추얼 기록
- 과제지속력 ↔ `26일 기록을 연 날` / 리추얼 기록
- 보조 확인 ↔ `결석 0일`, `확정 출석 26/27일` / 내 출석 기록

출석률은 저장·생성·표시하지 않는다. `내 제출 현황` 원자료가 없다는 사실은 근거 영역 하단에 한 줄로 안내하고, 제출률을 임의로 계산하지 않는다.

### 대표작·문서·갱신 장치

10번 논문은 실제 PDF 링크가 있는 파일 표지형 카드로 둔다. 13번 앱은 “완료 후 링크 연결”이라는 준비 카드로 남긴다. 지원 문서 다운로드는 대표작 다음에 배치한다. 갱신 장치는 사이트 안에서 과장하지 않고 README와 ZIP에서 확인할 수 있도록 하며, 필요하면 “새 기록 → 후보 생성 → 사람 승인 → 빌드” 네 단계의 작은 안내를 문서 영역에 둔다.

## 시각 방향

- 색상: 블랙 `#08090A`, 차콜 `#121416`, 오렌지 `#FF6A00`, 종이 `#F4F1E8`, 본문 회색 `#35393E`
- 글꼴: `Space Grotesk`는 영문·숫자·짧은 표제, `Noto Sans KR`는 한국어 본문, `DM Mono`는 날짜·출처·작은 메타 정보에 사용
- 정렬: 모든 본문은 왼쪽 정렬. 본문 줄 길이는 80자 이하를 목표로 하고, 작은 출처가 본문보다 시선을 끌지 않게 한다.
- 형태: 둥근 카드를 반복하지 않고, 크림색 이야기 면·주황색 능력 요약 면·차콜색 근거 면의 세 가지 큰 장면으로 구분한다.
- 장식: 실제 의미가 있는 날짜·구분선·단계 표시만 사용한다. 설명 없는 궤적선·점·통계 장식은 제거한다.
- 움직임: 히어로의 단계 그래픽은 한 번만 약하게 움직이고, 아래 콘텐츠는 짧은 진입 reveal만 사용한다. `prefers-reduced-motion`에서는 모두 정지한다.
- 접근성: `:focus-visible`, 충분한 명도 대비, 320px 이상 반응형, 긴 제목 줄바꿈, 링크의 명확한 동작 이름을 보장한다.

## 구현 경계

- React/Vite와 현재 결정적 generator 구조를 유지한다.
- `approved.json`은 사람이 승인한 사실, `site-data.json`은 generator가 계산한 근거로 분리한다.
- 외부 AI 호출, 로그인, 데이터베이스, 댓글, 방문자 통계는 추가하지 않는다.
- 공개 이메일과 HTTPS URL은 사용자가 확정하기 전까지 placeholder 상태로 남긴다.
- 문서·ZIP은 화면 콘텐츠와 같은 사실 순서를 사용하도록 다시 생성한다.

## 검증 기준

1. 이야기 본편이 1,300~1,500자 내외이고 2022 고난 → 바꾼 행동 → 2026 현재의 순서를 가진다.
2. 세 능력이 각각 날짜가 있는 장면과 연결된다.
3. 회복탄력성·과제지속력의 숫자는 이야기 뒤 근거 영역에 있고, 각 숫자에 출처가 있다.
4. 화면에 출석률, 임의의 제출률, 다른 사람의 실명이 없다.
5. 10번 논문 링크와 13번 앱 준비 자리가 있다.
6. 같은 입력을 두 번 넣은 generator 결과가 byte-identical이다.
7. `npm run test:generator`, `npm run check:privacy`, `npm run build`가 통과한다.
8. 1280px·879px·390px 화면에서 가로 overflow, 잘린 제목, 겹치는 본문, 읽기 어려운 작은 글자가 없다.
9. 새 브라우저에서 로컬 사이트와 PDF·DOCX 링크가 인증 없이 열리고 런타임 오류가 없다.
